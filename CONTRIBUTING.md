# Overview

Maintaining the integrity and consistency of the project is of the utmost importance. This project adheres to the following Contributing document and can be viewed and downloaded at any time. By being a code contributor for this project, you hereby agree to follow the guidelines outlined here.

## Contributing Guidelines

### Project Code

* Should have tab indentations consisting of four (4) column spaces per tab
* Should have braces on its own line by itself and aligned in the same column where the code started in control flow statements, such as if-else, for, try-catch, and functions
* Should not have optional braces for control flow statements with only one (1) code statement
* Should not have any leading, except for tab indentations, or trailing white spaces
* Should not have a trailing comma in the last array or object item declaration
* Should always address warnings, through code changes or issue reporting, introduced by frameworks
* Should never suppress warnings introduced by frameworks
* Should be `camelCase` for variable names and method names, `CamelCase` for React component names and MongoDB model names, and `camel-case` for CSS rules and JavaScript file names

### Project Commits

* Should have a maximum of fifty (50) characters for the commit title
* Should have a maximum of seventy-two (72) characters per line for the commit description
* Should be in the present tense
* Should not end with punctuation
